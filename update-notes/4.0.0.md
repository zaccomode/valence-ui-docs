# 4.0.0

Valence 4 replaces the fixed set of fill variants with a composable **material** system, adds a declarative **animation** system, and moves the library to React 19.

This is a breaking release. The migration is mostly mechanical — see the mapping tables below.

## Breaking changes

### `variant` is now `material`

The `FillVariant` type and the `variant` prop are gone from every component. Pass a [material](../core-concepts/materials/README.md) instead.

<table data-full-width="true"><thead><tr><th width="200">3.x</th><th>4.0</th></tr></thead><tbody><tr><td><code>variant="subtle"</code></td><td><code>material={new AirMaterial()}</code></td></tr><tr><td><code>variant="light"</code></td><td><code>material={new GlassMaterial()}</code></td></tr><tr><td><code>variant="filled"</code></td><td><code>material={new SolidMaterial()}</code></td></tr><tr><td><code>variant="paper"</code></td><td><code>material={new PaperMaterial()}</code></td></tr><tr><td><code>variant="outlined"</code></td><td><code>material={new PaperMaterial({ elevation: 0 })}</code>, or an <code>AirMaterial</code> with a border override</td></tr></tbody></table>

The `color` prop that used to sit alongside `variant` now belongs to the material:

```tsx
// 3.x
<Button variant="filled" color="blue">Save</Button>

// 4.0
<Button material={new SolidMaterial({ color: "blue" })}>Save</Button>
```

### The `shadow` prop is gone

Shadows are now a property of the material that produces them. `PaperMaterial` and `SolidMaterial` both take an `elevation` from 1 to 5.

```tsx
// 3.x
<Button variant="filled" shadow>Save</Button>

// 4.0
<Button material={new SolidMaterial({ elevation: 3 })}>Save</Button>
```

### `ValenceProvider` defaults changed

`defaults.variant`, `defaults.transitionDuration` and `defaults.shadow` were removed. `defaults` now only holds `size` and `radius`. Default materials live in a new `materials` object:

```tsx
// 3.x
<ValenceProvider
  defaults={{
    size: "sm",
    radius: "sm",
    variant: "light",
    transitionDuration: "0.1s",
    shadow: "0px 10px 30px rgba(0, 0, 0, 0.2)",
  }}
/>

// 4.0
<ValenceProvider
  defaults={{ size: "sm", radius: "sm" }}
  materials={{
    button: new GlassMaterial(),
    input: new GlassMaterial({ color: "black" }),
    card: new PaperMaterial(),
  }}
/>
```

Transition durations and shadows are now decided by each material.

### `StyledFlex` was removed

`Flex` absorbed its capability. Pass a `material` and a `radius` to `Flex` directly:

```tsx
// 3.x
<StyledFlex variant="paper" radius="md">…</StyledFlex>

// 4.0
<Flex material={new PaperMaterial()} radius="md">…</Flex>
```

### The `motion` prop is now `animation`

Most components used a `motion` prop typed as `MotionBehaviourProps`. That is replaced by `animation`, which also covers enter/exit transitions. See [Animations](../core-concepts/animations.md).

```tsx
// 3.x
<Button motion={{ onHover: "grow", onTap: "shrink" }}>Save</Button>

// 4.0
<Button animation={{ hoverAnimation: "grow", tapAnimation: "shrink" }}>Save</Button>
```

`UnstyledButton` still uses the older `motion` prop.

### `style` is now an Emotion `CSSObject`

`GenericProps.style` changed from `CSSProperties` to Emotion's `CSSObject`. This is a widening — everything valid before is still valid — but it now also accepts nested selectors:

```tsx
<Flex style={{ "&:hover": { opacity: 0.8 } }}>…</Flex>
```

### React 19 is required

`react` and `react-dom` are pinned as peer dependencies at `19.1.0`. Motion moved from `framer-motion` to `motion` v12.

## New features

### Materials

Four materials ship in the box — [Air](../core-concepts/materials/air-material.md), [Glass](../core-concepts/materials/glass-material.md), [Paper](../core-concepts/materials/paper-material.md) and [Solid](../core-concepts/materials/solid-material.md) — and you can [write your own](../core-concepts/materials/README.md#writing-your-own-material). Materials are immutable; every setter returns a copy, so they are safe to share and to store in the theme.

### Animations

The new [`useAnimation`](../valence-core/hooks/useanimation.md) hook builds Motion variants from named animations and respects `prefers-reduced-motion` automatically. `Text`, `Icon`, `Loader` and every button accept an `animation` prop.

### Layout animations

Polymorphic components accept Motion's `layout` prop for automatic position and size transitions.

### Multi-material components

Some components take more than one material, so each of their states can be styled independently:

* `Switch` takes `materials` with `buttonNormal`, `buttonActive`, `handleNormal` and `handleActive`.
* `PillSelector` takes `materials` with `regular`, `selected`, `input` and `button`.

## Migration checklist

1. Upgrade to React 19 and replace `framer-motion` with `motion` if you import it directly.
2. Find every `variant=` and replace it using the table above.
3. Find every `color=` on a button, input or card and move it into the material.
4. Remove `shadow` props; use `elevation` on `PaperMaterial` or `SolidMaterial`.
5. Update your `ValenceProvider`: trim `defaults` and add `materials`.
6. Replace `StyledFlex` with `Flex` plus a material.
7. Rename `motion` props to `animation` and update their shape.

## Known issues

The following are known defects in 4.0.2 and are being tracked for 4.1. Check the repository's `docs/V4-RELEASE-FIXES.md` for the current status.

* `disabled` is not forwarded to the underlying element by `PrimitiveButton`, so disabled buttons remain clickable and focusable.
* Passing `colors` to `ValenceProvider` **replaces** the default palette rather than extending it. Until this is fixed, include `DEFAULT_PALETTE` yourself: `colors={[...DEFAULT_PALETTE, myColor]}`.
* Clearing a `NumberInput` emits `NaN` to `setValue`.
* `SelectInput` matches its `value` against `options` by reference, so a structurally equal value will not resolve.
* `Slider`, `RangeSlider` and `Switch` discard props they do not explicitly handle, including `id`, `className` and `aria-*`.
* The library reads `window` during render, so it cannot be server-rendered. Import Valence components in client components only.
